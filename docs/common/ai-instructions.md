## 지시문 (복사해서 사용)

```
너는 FridgeMate 팀 프로젝트의 개발을 돕는다. 아래 규칙을 반드시 지켜라.

[프로젝트]
- FridgeMate: 냉장고 식재료를 등록하고 소비기한을 관리하는 웹 앱(PWA)
- 서버 없이 브라우저에서만 동작한다 (R1). 회원가입·가족 공유·웹 푸시는 만들지 않는다 (R2).

[구조]
- 시스템은 외부 시설 / 내부 논리 계층(L0~L7) / 사용자·외부 연계 3영역으로 나뉜다.
- 내부 논리 계층: L0–L1 입력 수집·검증, L2–L3 메시지·저장, L4–L5 AI·분석, L6 업무·알림, L7 화면
- 첨부한 체계 구성도의 계층과 모듈 ID(bus, store, register, ocr, list, status, recipe, process, notify, settings, backup)를 그대로 쓴다.

[규칙]
1. 나는 [내 모듈 이름, 예: register]만 맡는다. 다른 모듈의 코드는 만들거나 고치지 않는다.
2. 모듈끼리 함수를 직접 호출하지 않는다. 모든 정보는 메시지 버스로 표준 메시지를 보내 주고받는다.
3. 표준 메시지는 from, to, type, timestamp, format, payload 6칸이다. 메시지 종류와 데이터 형식은 첨부한 인터페이스 정의서에 있는 것만 쓴다.
4. IndexedDB는 store 모듈만 다룬다. 내 모듈은 저장·조회를 메시지로 요청한다.
5. 화면(L7) 코드에 저장·판정 로직을 넣지 않는다. 화면은 받은 메시지 결과만 표시한다.
6. 인터페이스 정의서에 없는 메시지나 칸이 필요하면 코드를 만들지 말고 "인터페이스 변경 요청이 필요함"이라고 먼저 알려라.
7. 작업이 끝나면 진행 관리(progress-tracker.md)에 추가할 내용을 한두 줄로 정리해 줘라.

[이번 작업]

```
