# FridgeMate 인터페이스 요구사항 명세서

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | FridgeMate: OSS 기반 냉장고 식재료·유통기한 관리 서비스 |
| 관련 Issue | [Issue #5] 비기능·데이터·인터페이스 요구사항 정의 |
| 입력 문서 | 운용개념서(시스템 경계와 외부개체), 기능 요구사항 명세서 |
| 작성자 / Reviewer | 이지선 / 이정남 |
| 작업 Branch | `docs/5-nfr-interface` |
| 문서 버전 | v0.1 (Sprint 2 초안) |

## 2. 목적

사용자 단말, 카메라, 서버, 외부 상품 DB, 레시피 데이터, 푸시 알림 서비스 사이에서 주고받는 정보와 통신·보안·오류처리 조건을 정의한다. 특정 OSS 제품을 정하기 전 단계이므로 필요한 기능과 표준 중심으로 작성한다.

## 3. 인터페이스 목록

| ID | Interface | 송신 | 수신 | 주요 데이터 |
|---|---|---|---|---|
| IF-01 | Camera-Barcode Scanner | 스마트폰 카메라 | 바코드 인식 모듈 | 영상 프레임 → 바코드 번호 |
| IF-02 | Product Lookup | 서버 | 공개 상품 DB | 바코드 → 상품명, 분류, 이미지 |
| IF-03 | Web Client-API | 웹 화면(PWA) | 서버 API | 식재료, 그룹, 설정, 기록 |
| IF-04 | Authentication | 웹 화면 | 인증 서비스 | 이메일, 비밀번호, Token |
| IF-05 | Push Notification | 서버 | 브라우저 푸시 서비스 | 알림 제목, 내용, 이동 화면 |
| IF-06 | Recipe Data | 서버 | 레시피 데이터 | 재료 목록 → 레시피 목록 |
| IF-07 | Offline Storage | 웹 화면 | 단말 저장소 | 식재료 목록 사본, 변경 대기 목록 |

## 4. 공통 요구사항

| ID | 인터페이스 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-COM-001 | 서버 API는 JSON 형식으로 요청과 응답을 주고받아야 한다. | P0 | I/T |
| IR-COM-002 | 모든 API 응답은 성공 여부, 데이터, 오류 코드와 오류 메시지를 포함해야 한다. | P0 | I/T |
| IR-COM-003 | 날짜는 YYYY-MM-DD, 시각은 ISO 8601 형식을 사용해야 한다. | P0 | I |
| IR-COM-004 | 외부 서비스 호출은 5초 안에 응답이 없으면 실패로 처리하고 대체 흐름으로 넘어가야 한다. | P0 | T |

## 5. IF-01 Camera-Barcode Scanner

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-CAM-001 | 바코드 인식은 브라우저에서 카메라 권한을 받아 동작해야 한다. | P0 | T |
| IR-CAM-002 | EAN-13, EAN-8, UPC-A 바코드를 인식해야 한다. | P0 | T |
| IR-CAM-003 | 카메라 권한이 거부되면 바코드 번호 직접 입력 화면으로 전환해야 한다. | P0 | T |
| IR-CAM-004 | 바코드 영상은 서버로 전송하지 않고 단말에서 인식해야 한다. | P1 | I |

## 6. IF-02 Product Lookup

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-PRD-001 | 서버는 바코드 번호로 공개 상품 DB(예: Open Food Facts)를 조회해야 한다. | P0 | T |
| IR-PRD-002 | 조회 결과는 상품명, 분류, 이미지 URL, 출처를 포함해야 한다. | P0 | I/T |
| IR-PRD-003 | 조회 결과는 30일간 캐시하여 같은 바코드의 반복 조회를 줄여야 한다. | P1 | T |
| IR-PRD-004 | 국내 상품 보강을 위해 국내 공공 식품 데이터 연동을 추가할 수 있는 구조여야 한다. | P2 | A |
| IR-PRD-005 | 외부 DB의 이용 조건(호출 제한, 라이선스, 출처 표시)을 준수해야 한다. | P0 | I |

## 7. IF-03 Web Client-API

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-API-001 | API는 식재료 등록·조회·수정·삭제·소비/폐기 처리 기능을 제공해야 한다. | P0 | T |
| IR-API-002 | API는 그룹 생성, 초대 링크 생성·수락, 구성원 제외 기능을 제공해야 한다. | P1 | T |
| IR-API-003 | API는 로그인한 사용자의 Token을 확인한 뒤에만 응답해야 한다. | P0 | T |
| IR-API-004 | 식재료 목록 API는 보관 위치, 상태, 정렬 조건으로 조회할 수 있어야 한다. | P1 | T |

### 7.1 식재료 데이터 예시

```json
{
  "itemId": "itm_0123",
  "groupId": "grp_0007",
  "name": "우유 1L",
  "category": "유제품",
  "barcode": "8801234567890",
  "quantity": 1,
  "unit": "개",
  "storage": "냉장",
  "expiryDate": "2026-10-15",
  "status": "임박",
  "createdBy": "user_01",
  "updatedAt": "2026-10-12T09:30:00+09:00"
}
```

## 8. IF-04 Authentication

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-AUT-001 | 인증 서비스는 로그인 성공 시 만료 시간이 있는 Token을 발급해야 한다. | P0 | T |
| IR-AUT-002 | Token에는 사용자 ID와 소속 그룹 정보를 확인할 수 있는 값이 있어야 한다. | P0 | I/T |
| IR-AUT-003 | 로그아웃하면 단말에 저장된 Token을 삭제해야 한다. | P1 | T |

## 9. IF-05 Push Notification

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-PSH-001 | 알림은 Web Push 표준으로 Android Chrome과 iOS Safari(홈 화면 설치 시)에 보낼 수 있어야 한다. | P0 | T |
| IR-PSH-002 | 알림 메시지는 제목, 내용, 누르면 이동할 화면 주소를 포함해야 한다. | P0 | I/T |
| IR-PSH-003 | 발송 결과(성공·실패)를 알림 기록에 저장해야 한다. | P1 | T |
| IR-PSH-004 | 만료된 푸시 구독 정보는 자동으로 정리해야 한다. | P2 | T |

### 9.1 알림 메시지 예시

```json
{
  "title": "유통기한 알림",
  "body": "우유 1L 외 2개가 곧 유통기한이에요",
  "url": "/items?status=expiring",
  "sentAt": "2026-10-12T09:00:00+09:00"
}
```

## 10. IF-06 Recipe Data

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-RCP-001 | 서버는 재료 목록을 입력하여 레시피 목록을 조회할 수 있어야 한다. | P1 | T |
| IR-RCP-002 | 레시피 데이터는 레시피명, 재료 목록, 조리 방법 또는 원문 링크를 포함해야 한다. | P1 | I |
| IR-RCP-003 | 레시피 데이터 출처와 이용 조건을 확인하고 화면에 출처를 표시해야 한다. | P1 | I |

## 11. IF-07 Offline Storage

| ID | 요구사항 | 우선순위 | 검증 |
|---|---|---:|---:|
| IR-OFF-001 | 웹 화면은 마지막으로 받은 식재료 목록을 단말 저장소에 보관해야 한다. | P2 | T |
| IR-OFF-002 | 오프라인 중 변경 요청은 순서대로 보관했다가 연결 복구 후 서버에 보내야 한다. | P2 | T |

## 12. 인터페이스 검토 체크리스트

- [ ] 운용개념서의 외부개체가 모두 인터페이스 목록에 있다.
- [ ] 외부 서비스 장애 시의 대체 흐름이 정의되었다.
- [ ] 외부 데이터의 라이선스·출처 표시 조건이 반영되었다.
- [ ] 3주차 OSS 후보 조사에 필요한 기능(바코드 인식, 상품 DB, 인증, 푸시, 저장소)이 식별되었다.
