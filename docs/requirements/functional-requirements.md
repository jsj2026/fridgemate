## 2. 목적과 작성규칙

본 문서는 운용개념서의 시나리오(SCN)와 User Class(UC)에서 도출한 시스템 기능을 정의한다. 각 요구사항은 "시스템은 ~해야 한다" 형식으로 쓰고, 고유 ID, 출처, 우선순위, 검증방법을 포함한다.

### 2.1 우선순위

| 등급 | 의미 |
|---|---|
| P0 | 서비스 목적에 꼭 필요한 MVP 필수 기능 |
| P1 | 핵심 사용을 돕는 기능으로 이번 범위에서 구현 권고 |
| P2 | 일정에 따라 후속 Sprint에서 구현 가능 |

### 2.2 검증방법

| 코드 | 방법 | 설명 |
|---|---|---|
| T | Test | 입력·조건·예상결과로 시험 |
| D | Demonstration | 실제 화면이나 사용 흐름 시연 |
| I | Inspection | 문서, 설정, 화면 구성 검토 |

## 14. 카메라 인식 기능 AI 활용 제안

카메라 촬영 및 AI 이미지 분석 기능 요구사항

1. 개발 목적

식품 등록 시 제품명과 소비기한을 직접 입력하는 불편을 줄이기 위해, 스마트폰 카메라와 AI 이미지 분석을 활용한 자동 입력 기능을 개발한다.

2. 주요 기능 요구사항

FR-ERR-01

오류 처리

카메라 권한 거부, 네트워크 오류, 인식 실패 시 수동 입력을 지원한다.

필수

3. 사용자 처리 절차

제품 촬영 버튼 선택

1단계: 제품 앞면 촬영

2단계: 소비기한 부분 촬영

무료 OCR 또는 AI 이미지 분석 선택

상품명과 소비기한 자동 추출

인식 결과 확인 및 수정

냉장·냉동·실온 보관 위치 선택

최종 식품 등록

4. AI 기술 적용 방안

초기 버전은 Tesseract.js를 활용한 무료 OCR을 지원한다.

고정밀 분석을 위해 OpenAI 비전 모델 등의 AI 이미지 분석 API를 추가한다.

AI 분석 시 제품 앞면과 소비기한 사진을 함께 활용한다.

API 키는 서버 환경변수로 관리하고 브라우저에 노출하지 않는다.

AI 분석은 사용자 요청 시에만 실행한다.

AI 분석 결과는 사용자가 반드시 확인하도록 한다.

5. 이미지 인식률 개선 방안

제품명과 소비기한을 분리 촬영한다.

촬영 이미지의 해상도를 최대한 유지한다.

이미지 확대, 자르기, 밝기 및 대비 보정 기능을 검토한다.

제품명과 소비기한의 인식 정확도를 별도로 평가한다.

6. 기존 프로그램과의 호환성

기존 식품 등록·삭제 기능을 유지한다.

기존 냉장·냉동·실온 분류 기능을 유지한다.

기존 소비기한 관리 및 알림 표시 기능을 유지한다.

사용자 확인 없이 인식 결과를 자동 저장하지 않는다.

7. 개발 및 테스트 기준

아이폰 Safari와 안드로이드 Chrome에서 카메라 기능을 테스트한다.
