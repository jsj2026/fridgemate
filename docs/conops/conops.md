## 2. 운용 목적

FridgeMate의 운용 목적은 사용자가 냉장고 속 식재료와 유통기한을 쉽게 파악하고, 기한이 지나기 전에 소비하도록 돕는 것이다. 시스템은 알림과 추천을 제공하는 도구이며, 식재료의 실제 상태(변질 여부)를 판단하거나 보장하지 않는다.

## 3. 운용환경

| 구분 | 운용환경 |
|---|---|
| 사용 장소 | 가정 (주방, 장보기 직후, 마트에서 보유 재료 확인) |
| 사용자 단말 | 스마트폰 브라우저(PWA 설치 가능), PC 브라우저 |
| 입력 장치 | 스마트폰 카메라(바코드 스캔), 화면 터치·키보드 |
| 서버환경 | 교육용 Cloud 또는 무료 호스팅 환경 |
| 네트워크 | 가정 Wi-Fi, 모바일 데이터. 일시적 오프라인 가능 |
| 외부 서비스 | 공개 상품 DB, 레시피 데이터, 브라우저 푸시 서비스 |
| 운용시간 | 24시간 사용 가능, 알림은 사용자가 정한 시각(기본 오전 9시)에 발송 |

## 4. 시스템 경계와 외부개체

| 외부개체 | 시스템과 교환하는 정보 | 책임경계 |
|---|---|---|
| 사용자 | 식재료 정보, 소비·폐기 처리, 알림 설정 | 실제 식재료 상태 확인은 사용자 책임 |
| 스마트폰 카메라 | 바코드 영상 | 카메라 권한 허용은 사용자·OS 책임 |
| 공개 상품 DB | 바코드 → 상품명, 분류, 이미지 | 데이터 정확성과 가용성은 외부 책임 |
| 레시피 데이터 | 레시피명, 재료 목록, 조리 링크 | 데이터 정확성은 외부 책임 |
| 브라우저·OS 푸시 서비스 | 알림 메시지 | 최종 전달 성공은 외부 서비스 영향 |

## 5. 운용 전·후 비교

| 구분 | 도입 전 | 도입 후 |
|---|---|---|
| 보유 재료 확인 | 냉장고를 직접 열어 확인 | 앱에서 보관 위치별 목록 확인, 장보는 중에도 확인 |
| 유통기한 관리 | 기억이나 메모에 의존 | D-day 표시와 임박 알림(D-3, D-1, 당일) |
| 등록 방식 | 메모 앱에 손으로 입력 | 바코드 스캔 후 유통기한만 입력 |
| 가족 공유 | 말로 전달하거나 공유 안 됨 | 같은 냉장고 그룹에서 목록 공유 |
| 메뉴 결정 | 재료를 보고 즉흥적으로 결정 | 임박 재료 중심 레시피 추천 |
| 폐기 파악 | 얼마나 버리는지 알 수 없음 | 소비·폐기 기록과 월별 요약 |

## 6. 상위 운용흐름

1. 사용자가 장을 본 뒤 바코드를 스캔하거나 직접 입력하여 식재료를 등록한다.
2. 시스템이 상품 정보를 조회하여 이름과 분류를 채우고, 사용자가 유통기한과 보관 위치를 확인·입력한다.
3. 시스템이 보관 위치별 목록에 식재료와 남은 기간(D-day)을 표시한다.
4. 매일 정해진 시각에 시스템이 유통기한 임박 식재료를 판별하여 알림을 보낸다.
5. 사용자가 알림이나 목록에서 임박 식재료를 확인하고, 필요하면 레시피 추천을 본다.
6. 사용자가 식재료를 먹으면 "소비", 버리면 "폐기"로 처리한다.
7. 시스템이 소비·폐기 기록을 모아 월별 요약을 보여준다.

## 7. 운용모드

| 운용모드 | 진입조건 | 주요기능 | 종료조건 |
|---|---|---|---|
| OM-01 정상 | 네트워크와 서버 정상 | 등록, 조회, 알림, 추천, 공유 | 오프라인 또는 장애 발생 |
| OM-02 오프라인 | 단말 네트워크 끊김 | 마지막 동기화 목록 조회, 변경 내용 임시 저장 | 네트워크 복구 후 동기화 완료 |
| OM-03 외부서비스 장애 | 상품 DB 또는 레시피 데이터 응답 없음 | 직접 입력으로 등록, 추천 기능 일시 중단 안내 | 외부 서비스 복구 |
| OM-04 점검 | 서비스 배포·점검 | 점검 안내 표시, 조회 위주 제한 운용 | 점검 완료 |

## 8. 식재료 상태와 알림 개념

### 8.1 식재료 상태

| 상태 | 조건 | 화면 표시 |
|---|---|---|
| 여유 | 유통기한까지 4일 이상 | 초록색 + "D-n" |
| 임박 | 유통기한까지 1~3일 | 주황색 + "임박 D-n" |
| 오늘까지 | 유통기한 당일 | 빨간색 + "오늘까지" |
| 기한 경과 | 유통기한이 지남 | 회색 + "기한 지남" |
| 소비 완료 | 사용자가 소비 처리 | 목록에서 제외, 기록에 보관 |
| 폐기 | 사용자가 폐기 처리 | 목록에서 제외, 기록에 보관 |

### 8.2 상태 전이

```
등록 → 여유 → 임박 → 오늘까지 → 기한 경과
          ↘        ↘          ↘          ↘
                 소비 완료 / 폐기 (어느 상태에서든 사용자가 처리)
```

### 8.3 알림 개념
- 기본 알림 시점은 D-3, D-1, 당일이며 사용자가 끄거나 바꿀 수 있다.
- 같은 날 알림 대상이 여러 개면 하나의 요약 알림으로 묶어 보낸다.
- 기한 경과 품목은 알림 대신 목록 상단에 "확인 필요"로 표시하여 소비·폐기 처리를 유도한다.

## 10. 핵심 운용 시나리오

### SCN-01 바코드로 식재료 등록

| 항목 | 내용 |
|---|---|
| 목적 | 장 본 가공식품을 빠르게 등록 |
| 주 Actor | UC-01 1인 가구 사용자, UC-02 가족 공유 사용자 |
| 사전조건 | 로그인 상태, 카메라 권한 허용 |
| 종료조건 | 식재료가 목록에 표시됨 |

**기본 흐름**
1. 사용자가 "바코드로 등록"을 누른다.
2. 카메라로 상품 바코드를 비춘다.
3. 시스템이 바코드를 인식하고 상품 DB에서 상품명과 분류를 조회한다.
4. 시스템이 상품명, 분류, 기본 보관 위치를 채운 등록 화면을 보여준다.
5. 사용자가 유통기한과 수량을 확인·입력하고 저장한다.
6. 시스템이 목록에 식재료와 D-day를 표시한다.

**대체·예외 흐름**
- 상품 DB에 정보가 없으면 상품명 입력칸을 비워 두고 직접 입력하게 한다. (SCN-06)
- 같은 상품이 이미 있으면 "수량을 추가할까요?"를 묻는다.

**성공기준**
- 바코드 인식부터 저장까지 10초 이내
- 상품 DB에 있는 상품은 상품명이 자동으로 채워짐

### SCN-02 직접 입력으로 식재료 등록

| 항목 | 내용 |
|---|---|
| 목적 | 바코드가 없는 신선식품(채소, 육류 등) 등록 |
| 주 Actor | UC-01, UC-02 |
| 사전조건 | 로그인 상태 |
| 종료조건 | 식재료가 목록에 표시됨 |

**기본 흐름**
1. 사용자가 "직접 입력"을 누른다.
2. 이름을 입력하면 시스템이 자주 쓰는 품목을 자동완성으로 제안한다.
3. 시스템이 품목 분류별 권장 보관 기간으로 유통기한을 미리 채운다.
4. 사용자가 유통기한, 수량, 보관 위치를 확인하고 저장한다.

**성공기준**
- 자동완성 품목 선택 시 3번 이내의 터치로 등록 완료

### SCN-03 유통기한 임박 알림과 소비 처리

| 항목 | 내용 |
|---|---|
| 목적 | 기한 전에 식재료를 소비하도록 유도 |
| 주 Actor | UC-01, UC-02 |
| 사전조건 | 알림 권한 허용, 임박 식재료 존재 |
| 종료조건 | 식재료가 소비 또는 폐기로 처리됨 |

**기본 흐름**
1. 매일 알림 시각에 시스템이 D-3, D-1, 당일 해당 품목을 찾는다.
2. 시스템이 "우유 외 2개가 곧 유통기한이에요" 형태의 요약 알림을 보낸다.
3. 사용자가 알림을 눌러 임박 품목 목록을 연다.
4. 사용자가 먹은 품목을 "소비"로 처리한다.
5. 시스템이 해당 품목을 목록에서 빼고 소비 기록에 남긴다.

**대체·예외 흐름**
- 알림 권한이 없으면 앱을 열 때 화면 상단에 임박 품목을 표시한다.
- 그룹 구성원이 이미 소비 처리했으면 다른 구성원에게는 알림을 보내지 않는다.

**성공기준**
- 알림 대상 품목이 누락 없이 정해진 날에 알림에 포함됨

### SCN-04 가족과 냉장고 공유

| 항목 | 내용 |
|---|---|
| 목적 | 가족 구성원과 같은 냉장고 목록을 함께 사용 |
| 주 Actor | UC-03 그룹 관리자, UC-02 가족 공유 사용자 |
| 사전조건 | 그룹 관리자가 냉장고 그룹을 생성함 |
| 종료조건 | 초대받은 구성원이 그룹 목록을 볼 수 있음 |

**기본 흐름**
1. 그룹 관리자가 "가족 초대"를 눌러 초대 링크를 만든다.
2. 관리자가 카카오톡 등으로 링크를 전달한다.
3. 가족 구성원이 링크로 가입·로그인하고 초대를 수락한다.
4. 구성원 화면에 그룹 식재료 목록이 표시된다.
5. 누군가 식재료를 등록·수정하면 다른 구성원의 목록에도 반영된다.

**대체·예외 흐름**
- 초대 링크는 7일 후 만료된다.
- 두 사람이 같은 품목을 동시에 수정하면 나중 수정이 반영되고 변경 내역에 둘 다 남는다.

### SCN-05 남은 재료로 레시피 추천

| 항목 | 내용 |
|---|---|
| 목적 | 임박 재료를 활용할 메뉴 결정 지원 |
| 주 Actor | UC-01, UC-02 |
| 사전조건 | 등록된 식재료 1개 이상 |
| 종료조건 | 사용자가 레시피를 확인함 |

**기본 흐름**
1. 사용자가 "오늘 뭐 먹지?"를 누른다.
2. 시스템이 보유 재료와 레시피 재료를 비교한다.
3. 임박 재료를 많이 쓰는 레시피부터 보여준다.
4. 레시피마다 "보유 재료 / 부족한 재료"를 표시한다.

**대체·예외 흐름**
- 레시피 데이터가 응답하지 않으면 "지금은 추천을 불러올 수 없어요"를 표시한다.

### SCN-06 바코드 인식 실패와 상품 정보 없음 (예외)

| 항목 | 내용 |
|---|---|
| 목적 | 자동 인식이 안 될 때도 등록을 끝낼 수 있게 함 |
| 주 Actor | UC-01, UC-02 |

**기본 흐름**
1. 10초 동안 바코드가 인식되지 않으면 "숫자로 직접 입력" 버튼을 보여준다.
2. 바코드가 인식됐지만 상품 DB에 없으면 상품명 직접 입력으로 넘어간다.
3. 사용자가 입력한 상품명은 해당 바코드와 함께 저장되어, 같은 그룹에서 다음에 스캔할 때 자동으로 채워진다.
4. 잘못된 상품 정보가 나오면 사용자가 "정보가 달라요"로 신고할 수 있다.

### SCN-07 오프라인 사용과 동기화 (예외)

| 항목 | 내용 |
|---|---|
| 목적 | 마트 등 네트워크가 약한 곳에서도 보유 재료 확인 |
| 주 Actor | UC-01, UC-02 |

**기본 흐름**
1. 네트워크가 끊기면 화면에 "오프라인" 표시가 나타난다.
2. 사용자는 마지막으로 동기화된 목록을 조회할 수 있다.
3. 오프라인 중 변경한 내용은 단말에 임시 저장된다.
4. 네트워크가 복구되면 시스템이 자동으로 서버와 동기화하고 결과를 알려준다.

## 11. 운용 정책

- 시스템은 유통기한 정보를 알려줄 뿐, 식재료의 안전성을 판단하지 않는다. 화면에 이 안내를 표시한다.
- 사용자 개인정보는 이메일과 닉네임만 수집한다.
- 외부 상품 DB의 데이터를 사용할 때는 출처를 표시한다.
- 삭제는 등록자 본인 또는 그룹 관리자만 할 수 있다.
